# Правила проекта PostField

- Язык рабочих заметок — русский. Публичные интерфейсы и комментарии допускают английский.
- Каждое изменение поведения: сначала тест и подтверждённое падение, затем минимальная реализация, затем рефакторинг. Фиксируй краткое доказательство в docs/TDD.md и PR.
- SOLID: core не импортирует браузер, DOM, HTTP, IndexedDB и delivery. Зависимости адаптеров передаются через узкие интерфейсы. Не вводи абстракции без роли.
- Сохраняй ручной индекс, предотвращай устаревшие ответы и смешивание адресов разных секций формы.
- Ключ пользователя доступен только привилегированным страницам расширения. Не передавай его content script, странице, sync storage или логам.
- В публичный Git не помещай секреты, реальные адреса пользователей, браузерные cookies или ссылки на приватные ранбуки.
- CI на pull_request не получает секреты публикации. Сборки — GitHub-hosted runners. Публикация — только доверенный release SHA основной ветки.
- Версия берётся из package.json. Все четыре manifest и release tag должны совпадать.
- Пакеты неизменны после выпуска. uploaded, submitted и published — разные состояния. При неопределённом исходе сначала readback, затем решение о повторе.
- Не называй адаптер Opera рабочим до живой проверки его HTTP-контракта и аутентификации; не заменяй API скрытой UI-автоматизацией.
- Целевые проверки, commit/push/PR, обязательный CI, проверка diff, merge и CI основной ветки. Без маркеров авторства агента.
