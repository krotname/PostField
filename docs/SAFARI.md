# Safari на macOS

Цель `safari` входит в `npm run build`. Она сохраняет Manifest V3, фоновый service worker и разрешения `activeTab`, `scripting`, `storage`, исключает `minimum_chrome_version` и неподдерживаемый Packager ключ `options_ui.open_in_tab`. Настройки открываются обычной страницей расширения.

## Сборка

Нужны macOS, Xcode с `xcrun safari-web-extension-packager`, Node.js и npm. Текущий сценарий собирает приложение для Apple Silicon. Проверенная среда: macOS 27.2.1, Safari 27.2, Xcode 27.2, Node.js 24.22.3.

```sh
npm ci
npm run check
npm run package:safari
```

Результаты:

- `dist/safari/` — ресурсы WebExtension;
- `artifacts/postfield-0.5.0-safari.zip` — архив ресурсов;
- `dist/safari-native/PostField/PostField.xcodeproj` — сгенерированный проект;
- `dist/safari-derived-data/Build/Products/Debug/PostField.app` — приложение с расширением.

Версия приложения и вложенного расширения берётся из `package.json`. Команда пересоздаёт сгенерированный проект, собирает его с подписью ad hoc и проверяет подпись. Браузерная сборка ориентирована на Safari 17.4, deployment target приложения — macOS 14.4; проверка на минимальных версиях пока не выполнялась.

## Локальная установка и проверка

1. Скопируйте `PostField.app` в папку приложений и запустите один раз.
2. В Safari разрешите неподписанные расширения в настройках разработчика, затем включите «PostField — почтовый индекс» в настройках расширений.
3. Предоставьте доступ только к тестовому сайту. Используйте искусственную форму с публичным адресом и выбранным источником индекса.
4. Проверьте заполнение пустого индекса, сохранение ручного индекса и сброс результата при изменении адреса.

Safari может отклонять автоматизированное включение расширений. Сборка и регистрация приложения не подтверждают выполнение сценария в браузере.

Подпись ad hoc подходит для локальной разработки. Подписанная дистрибуция и App Store требуют отдельного профиля выпуска; эта команда ничего не подаёт в магазины.
